# Прототипы и спецификация экранов

Интерактивный макет: [prototype/index.html](prototype/index.html). Он показывает логику и визуальное направление. Полное поведение будущего продукта определяет ТЗ; макет не заменяет хранение данных и синхронизацию.

## Карта переходов

```text
Любой основной экран → Записать мысль → Входящие
Входящие → Разобрать → Добавить результат → Добавить ещё → Завершить разбор
Сейчас / Действия → Карточка действия → Фокус → Выполнено
Проекты → Карточка проекта → Добавить ближайшее действие → Действия
Обзор → Шаг обзора → Решение / Сохранить и выйти → Продолжить
Ещё → Идеи → Создать проект → Проекты
Ещё → Ожидания → Создать действие контроля → Действия
Ещё → Календарь / Материалы / Настройки и данные
```

## S01. Сейчас

```text
┌──────────────┬───────────────────────────────────┬────────────────────┐
│ Ясный шаг    │ Сейчас                Записать   │ Договорённости     │
│ Сейчас      │ Что можно сделать дальше         │ 15:00 Созвон       │
│ Действия    │                                   │                    │
│ Входящие    │ ○ Написать семье о датах отпуска   │ Реальные сроки     │
│ Проекты     │   Семейная поездка     Начать      │ 18 ноя: документы  │
│ Обзор       │ ○ Открыть прототип, записать идеи  │                    │
│ Ещё         │ ○ Уточнить дату доставки          │ Обзор системы      │
│             │                                   │ Продолжить         │
│             │ Выбрать из недели                 │                    │
└──────────────┴───────────────────────────────────┴────────────────────┘
```

Отмеченное «Сейчас» — осознанный выбор на текущую дату. События и реальные сроки не становятся обычными задачами. В продукте порядок изменяется перетаскиванием и кнопками «Выше / Ниже» для клавиатуры. На телефоне вспомогательная колонка уходит под список, события остаются доступны без скрытых горизонтальных полос.

Пусто: «На сейчас ничего не выбрано. Можно выбрать действие из недели или закончить работу». После выполнения: ненавязчивое подтверждение с отменой. Если проект остался без шага — предложение открыть его, не блокирующее работу.

## S02. Записать мысль

Диалог с одним обязательным многострочным полем и кнопкой «Сохранить во входящие». URL необязателен. После успешной записи поле очищается, при ошибке текст остаётся. `Ctrl/Cmd+Enter` сохраняет, `Escape` закрывает; при непустом несохранённом тексте нужна возможность вернуться к вводу. На телефоне диалог занимает доступную высоту над клавиатурой, кнопка сохранения не перекрывается.

В продукте черновик локально восстанавливается после закрытия вкладки. Сохранённая запись появляется в инбоксе сразу, даже без сети. Состояние синхронизации показывается отдельно от факта сохранения.

## S03. Входящие и разбор

```text
┌──────────────────────┬─────────────────────────────────────────┐
│ Очередь              │ Исходная мысль                          │
│ Отпуск: даты и жильё │ «Проверить даты, созвониться…»           │
│ Гарантия на технику  │                                         │
│ Идея выходных       │ Что из этого следует?                   │
│                      │ [Действие] [Проект] [Встреча]            │
│                      │ [Материал] [Идея]                       │
│                      │ Формулировка                            │
│                      │ [Добавить в результаты]                 │
│                      │                                         │
│                      │ Результаты разбора:                     │
│                      │ • Действие: написать семье…             │
│                      │ • Проект: семейная поездка              │
│                      │ [Завершить разбор]                      │
└──────────────────────┴─────────────────────────────────────────┘
```

Открытие записи не меняет её статус. Каждый результат редактируется до подтверждения. В полной версии действие можно связать с проектом из того же пакета, а событию задать начало, конец и зону. Удаление результата из черновика не удаляет исходник. «Не нужно» доступно отдельно и отправляет исходник в корзину с возможностью восстановления.

На телефоне сначала очередь, затем отдельный экран разбора с кнопкой назад и сохранением черновика. После завершения приложение показывает созданные объекты; не начинает автоматически разбирать следующую запись. При нулевом числе результатов «Завершить разбор» недоступно: нужно добавить результат или осознанно выбрать «Не нужно».

## S04. Действия и карточка

Плоский список с переключателем горизонта. Поиск, необязательный фильтр проекта и завершённое — дополнительные средства, не обязательные этапы выбора. Карточка содержит формулировку, пояснение, проект, горизонт, реальный срок и ссылку. У реального срока объяснение: «Последний допустимый день, а не желание заняться». Пустая дата допустима.

«Переформулировать» сохраняет прежний текст в истории. «Отменить задачу» отличается от «Выполнить». В будущем продукте есть «Ожидаю результат» с полями договорённости. Прототип демонстрирует редактирование, перенос, завершение и отмену; история и фильтры описаны в ТЗ.

## S05. Проекты и карточка проекта

В списке видны название, результат, наличие ближайшего действия или пометка «Нужен следующий шаг». В карточке сначала показываются результат и действия, затем раскрываемые смысл, минимальный результат, справочный план и материалы. Создание возможно без полного плана. Вопрос-подсказка: «Какой небольшой шаг даст новую информацию или полезный результат?»

На завершении проекта с открытыми действиями продукт предлагает решить их судьбу; ничего не закрывает молча. При постановке на паузу действия сохраняются, но не попадают в активную очередь. Возобновление проекта предлагает пересмотр, а не возвращает старый выбор «Сейчас».

## S06. Фокус

Видно одно действие, его пояснение и связанный проект. Необязательный таймер 15/25/40 минут; выбор длительностей — решение дизайна, не норматив книги. Кнопки: начать/пауза, записать отвлечение, действие выполнено, выйти. Таймер не запускается сам при входе. На завершении интервала: «Отрезок закончился. Можно сделать паузу или продолжить». Никакого автоматического выполнения задачи.

Прототип показывает таймер и захват отвлечения; реальный продукт обязан восстанавливать сессию после сна устройства. Фоновое звуковое уведомление в MVP не обещается.

## S07. Обзор

Выбор ежедневного/еженедельного обзора. Один текущий шаг, короткий вопрос, соответствующий список объектов и действия над ними. Счётчик шагов описывает процесс, а не продуктивность. Шаг можно выполнить, пропустить с пометкой или отложить. Выход сохраняет прогресс.

Ежедневный шаблон: завершённые и следующие шаги → невыполненный вчерашний выбор → календарь и реальные сроки → выбор посильных действий. Еженедельный: источники входящих → актуальность действий → проекты без шага → завершённое и ожидания → календарь на 14 дней → выбор недели и проверка восстановления.

В продукте внутри шага доступны изменения записей и возврат в обзор с прежним состоянием. Прототип показывает переходы, сохранение прогресса в памяти вкладки и ссылки на тематические разделы. Завершение всех шагов с решениями отображает дату обзора. Наличие пропусков даёт статус «Частично», а не «Полностью завершён».

## S08. Идеи

Список с самым давним пересмотром вверху. Карточка: мысль, зачем сохранил, что можно добавить, когда пересматривал. Действия: оставить после просмотра, дополнить, создать проект, архивировать. От идеи не требуется срок выполнения. При создании проекта исходная идея сохраняет связь с ним и выходит из очереди инкубации.

## S09. Ожидания

Человек, ожидаемый результат, дата проверки, связанный проект. Кнопки: результат получен, перенести проверку, создать действие контроля. Дата проверки не означает, что другой человек нарушил обязательство. Просроченная проверка не вызывает автоматическое сообщение человеку.

## S10. Календарь

Простой список событий по дням: название, местное время, длительность, место. В полном продукте — создание, редактирование, события на весь день, недельное представление. Событие можно связать с проектом. Время занятости не используется как автоматическая оценка количества задач, которое человек «должен успеть». В макете — создание и просмотр событий, без внешних календарей.

## S11. Материалы

Поиск по названию и тексту, контекст проекта/задачи, ссылка на исходное место. Материал не получает чекбокс выполнения. В макете материалы, созданные при разборе, видны как записи. Полный редактор и поиск включены в ТЗ.

## S12. Настройки и надёжность

В продукте: часовой пояс, день обзора, источники входящих, состояние устройства и синхронизации, конфликты, экспорт/импорт, выход. Экран конфликта показывает две версии рядом с возможностью сохранить обе. При ошибке записи нельзя показывать «Сохранено».

В прототипе вместо имитации облака честное пояснение об ограничениях и кнопка сброса демонстрации. Это намеренный разрыв между макетом и продуктом.

## Обязательные общие состояния продукта

| Состояние | Что видит пользователь | Что сохраняется |
|---|---|---|
| Первая загрузка | Спокойный индикатор, затем контент или понятная ошибка | Введённый текст не затрагивается |
| Офлайн после первого входа | «Нет сети. Изменения сохраняются на устройстве» | Локальные записи и очередь синхронизации |
| Ошибка локальной записи | «Не удалось сохранить. Скопируйте текст или повторите» | Текст остаётся в поле |
| Сессия входа истекла | Повторный вход для синхронизации | Локальная работа остаётся доступной |
| Конфликт | Обе версии и конкретное решение | Обе версии до выбора |
| Пустая очередь | Объяснение и одно полезное действие | Никаких искусственных примеров без согласия |
| Удаление | Подтверждение результата и «Отменить»; запись в корзине | Возможность восстановления 30 дней |

## Доступность и адаптация

Продукт работает при ширине 360, 390, 768 и 1440 px, масштабировании текста и клавиатурной навигации. Диалоги имеют название, удерживают фокус и возвращают его к вызвавшей кнопке. Все действия доступны без drag-and-drop. Цели касания не меньше 44×44 px. Выбранная вкладка и ошибка обозначаются текстом/состоянием, а не только цветом. Скринридер получает сообщения о сохранении и ошибке без захвата фокуса. Интерфейс поддерживает reduced motion; анимация не нужна для понимания состояния.
