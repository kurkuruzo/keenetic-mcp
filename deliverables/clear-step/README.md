# Ясный шаг — актуальное ТЗ и прототипы

Текущая итерация от 15 ноября 2026 года. Предыдущая концепция целиком перенесена в [архив](../archive/README.md) и не является актуальным ТЗ.

## Документы для разработки

- [Техническое задание](requirements.md): согласованные решения, объём веб/PWA первой версии, функциональные и нефункциональные требования, приёмка.
- [Техническое описание и API](architecture.md): модель данных, единый API, работа офлайн, синхронизация, парольный вход, внешние инструменты и размещение на своём сервере.
- [Передача агенту-разработчику](implementation.md): порядок реализации, условия готовности этапов и отложенные решения.

Первая поставка — веб/PWA; отдельные Android/iOS-клиенты затем используют тот же API. Десктоп сейчас не рассматривается. Obsidian не изменяется, импорт и E2EE отложены. Встроенные инструменты отмечены как направление дальнейшего уточнения; API для внешних клиентов входит в первую версию.

## Демонстрационные экраны

- [Экран действий](actions.html): выбранные задачи из разных проектов, ручной порядок, выполнение, открытие карточки, контекст ближайшего действия.
- [Экран проекта](project.html): видение конечного результата, ближайшее целевое состояние, следующий конкретный шаг, план и справочная информация.

Под рабочей очередью нет общей ссылки на план одного проекта: действия могут относиться к разным проектам. Название проекта у задачи и ссылка в контексте ведут к соответствующему проекту. Верхняя навигация пока переключает два демонстрационных экрана; полноценный список проектов в эту итерацию не входит.

## Механика, согласованная с пользователем

Задача — одна запись с постоянным `id`, привязкой к проекту и признаком `inActions`. Создание задачи в плане не включает её в рабочую очередь. «Добавить в действия» включает показ этой же записи на экране действий и отмечает её в плане. «Убрать из действий» отключает показ, сохраняя задачу в плане. Выполнение и редактирование общие для обоих представлений. В карточку задачи можно попасть из любого представления.

Следующий конкретный шаг в проекте — первое по порядку выбранное невыполненное действие этого проекта. Он не копируется в отдельное текстовое поле. Если ни одно действие не выбрано, проект предлагает выбрать его из плана. Следующий пункт плана не активируется автоматически.

Названия трёх элементов взяты из §4.1.3 книги. Кнопки выбора, цветовое выделение и общий объект задачи — согласованная механика приложения. Она не заявляется дословной рекомендацией автора книги.

Название проекта, видение конечного результата и ближайшее целевое состояние редактируются через «Редактировать проект». У обоих полей результата есть явная кнопка «Изменить», открывающая редактор с фокусом в соответствующем поле. «Изменить шаг» открывает связанную задачу: её новая формулировка сразу отражается в плане и действиях. Правки проекта сохраняются в общем хранилище, включая название и контекст на экране действий; версия проекта защищает от перезаписи изменений из другой вкладки.

## Открытие

Для просмотра каждый HTML можно открыть непосредственно. Чтобы надёжно проверить общие данные между страницами и вкладками, запустите из корня checkout:

```powershell
node deliverables/clear-step/serve.mjs
```

Затем откройте:

- http://127.0.0.1:4177/actions.html
- http://127.0.0.1:4177/project.html

Сервер слушает только локальный компьютер и отдаёт только четыре файла прототипа. Остановка: Ctrl+C. Не меняйте адрес между `localhost` и `127.0.0.1`: это разные хранилища браузера. Порт также является частью адреса хранилища.

## Что попробовать

1. В проекте добавьте «Описать процесс разбора входящей записи» в действия.
2. Откройте экран действий: там появилась та же задача. Поднимите её кнопкой ↑.
3. Нажмите на название, измените формулировку и сохраните.
4. Вернитесь в проект: формулировка изменилась, задача отмечена «В действиях».
5. Выполните задачу в любом представлении. Она уйдёт из рабочей очереди и появится в выполненных задачах проекта. Следующее действие останется на экране действий.
6. Другую задачу уберите из действий: в плане она останется невыполненной.

Две вкладки на одном адресе получают изменения через событие `storage`. Сохранение читает последнее состояние; Web Locks последовательно выполняет записи там, где доступен. Редактор проверяет версию задачи, чтобы не затереть изменение другой вкладки. Без Web Locks одновременные записи не имеют той же гарантии; это прототип, не production-хранилище.

## Ограничения

Данные сохраняются в localStorage этого браузера. Нет аккаунта, серверной базы, переноса на телефон или облачной синхронизации. Очистка данных браузера удалит записи. При открытии через `file://` общее хранилище двух файлов зависит от браузера, поэтому для проверки связи используйте локальный сервер. В примерах нет реальных обязательств пользователя.

Быстрый ввод сохраняет мысли отдельно и позволяет увидеть их в том же диалоге. Разбор входящих, экраны идей и справочника в эту итерацию не входят. Блок справочной информации в проекте — демонстрационный текст. Визуальное направление: спокойная светлая поверхность, Segoe UI, зелёно-синий акцент выбора, без рейтингов и календаря; важная структура — очередь действий и связь с планом.

Синтаксис JS и отдача файлов проверяются отдельно от поведения браузера. Полная визуальная проверка и межвкладочный сценарий не считаются пройденными без фактической проверки в браузере.
