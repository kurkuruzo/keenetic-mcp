# Ясный шаг — техническое задание

Версия 1.0, 15.11.2026. Статус: согласованный пользователем объём и предлагаемые ниже правила реализации. Документ заменяет архивное широкое ТЗ. Это задание на разработку, а не описание уже готового приложения.

## 1. Назначение и основания

Личное приложение для управления задачами, проектами, идеями и справочной информацией. Главный сценарий: обдумать проект, выбрать конкретные задачи из плана в действия, выполнить их в выбранном порядке и видеть актуальный результат в проекте без дублирования записей.

Основания: решения пользователя в текущем обсуждении и приложенная книга Максима Дорофеева. Из книги берём разгрузку памяти, разбор входящих, конкретные следующие действия и разделение плана и рабочего списка (§3.2–3.5, 4.1.2). Поля проекта из §4.1.3: **видение конечного результата**, **ближайшее целевое состояние**, **следующий конкретный шаг**. Самостоятельная полезность промежуточного результата — ориентир §4.1.4, а не отдельное обязательное поле.

Книга определяет принципы, но не диктует интерфейс, API или стек. Механика «Добавить в действия» и единая запись задачи прямо предложены пользователем. Поля и правила первой версии, не оговорённые им отдельно, ниже являются предлагаемой базовой спецификацией; агенту не следует добавлять новые подсистемы по аналогии с прежним архивным ТЗ.

## 3. Этапы и границы

**R1 — первая рабочая версия:** адаптивный веб-клиент и устанавливаемая PWA, сервер/API, парольный вход, все сценарии F01–F14, офлайн-режим и синхронизация, JSON-экспорт и восстановление из него, экспорт Markdown, резервные копии. UI должен работать в мобильном браузере Android/iOS; это ещё не нативные приложения и не публикация в магазинах.

**R2 — мобильные приложения:** устанавливаемые Android/iOS-клиенты поверх того же API, с локальной БД и теми же доменными правилами. Выбор технологии клиентов и требования магазинов определить перед этим этапом. Наличие R2 не блокирует приёмку R1.

**Дальнейшее развитие, без включения в R1:** импорт Obsidian, сквозное шифрование, подключение внешних инструментов внутри приложения, MCP-адаптер, дополнительные способы захвата. Связь с Obsidian не реализовывать даже в фоне; хранилище пользователя не менять.

В R1 отсутствуют отдельные календарь, таймер, трекер привычек, баллы продуктивности, командные роли и автоматическое составление плана. Периодические обзоры поддерживаются возможностью просмотреть и изменить списки; отдельный движок ритуалов и расписаний не требуется. Встроенные инструменты не трактовать автоматически как ИИ-чат: состав, провайдеры и разрешённые действия нужно уточнить перед реализацией этого направления.

## 4. Термины и ключевые правила

- **Входящее** — сырая мысль или информация, ещё не разобранная. Не является задачей автоматически.
- **Задача** — единая запись с идентификатором и состоянием. Может принадлежать одному проекту или быть самостоятельной.
- **План проекта** — упорядоченные задачи проекта и Markdown-заметки. Задачи плана не обязаны быть выбраны для исполнения сейчас.
- **Действия** — представление выбранных невыполненных задач. Отдельной сущности-копии «действие» нет.
- **Проект** — конечный результат, к которому продвигаются через ближайшее целевое состояние и конкретные шаги.
- **Идея** — замысел без обязательства выполнить.
- **Материал** — справочная Markdown-запись без статуса выполнения.

Задача имеет независимые `status` и `inActions`. Выбор задачи не означает начало или завершение работы. Удаление из действий не удаляет её из проекта. Выполнение в любом представлении меняет один объект; завершение последней выбранной задачи не выбирает следующую из плана автоматически.

## 5. Функциональные требования

### F01. Аккаунт и устройства

Один личный аккаунт используется на всех устройствах владельца. Вход по логину и паролю, изменение пароля, выход, просмотр и отзыв серверных сессий. Регистрация публике закрыта; первоначального владельца создаёт оператор сервера через документированную команду со скрытым вводом пароля. Отдельного командного рабочего пространства нет.

Первый вход на новом устройстве требует сети. После успешной первоначальной синхронизации локальные данные доступны без сети. Истечение серверной сессии не должно стирать локальные изменения: повторный вход возобновляет синхронизацию. Сброс пароля владельца — документированная серверная процедура с отзывом сессий; email-доставка и публичный self-service reset не входят в R1.

### F02. Быстрый захват

Одно текстовое поле, сохранение без проекта, типа, даты и приоритета. Текст может содержать Markdown и ссылки. Запись появляется во входящих, не в действиях. После локального commit показать «Сохранено на устройстве», после server ack — «Синхронизировано». При ошибке сохранить текст в поле и предложить повтор/копирование. Черновик ввода восстанавливается после перезагрузки, насколько доступно локальное хранилище.

### F03. Разбор входящих

Показать исходный текст, подготовить один или несколько результатов: задача, проект, идея, материал. Позволить редактировать/удалять результаты черновика, связать задачу и материал с создаваемым в том же разборе проектом. До подтверждения исходник остаётся необработанным. Подтверждение атомарно создаёт результаты и связи с исходником, затем отмечает его обработанным.

Задачи из разбора по умолчанию не выбраны в действия. Проект создаётся с названием; видение и целевое состояние можно уточнить позднее, пустые поля явно показываются как неопределённые. Открытие входящего не считается разбором. «Не нужно» перемещает входящее в корзину без создания результатов. Повтор запроса после сетевого сбоя не создаёт дубликаты.

### F04. Задачи

Создание, открытие, редактирование названия, Markdown-пояснений, проекта и необязательного реального срока; выполнение, возврат в работу, отмена, восстановление, перенос в корзину. Обязателен только непустой заголовок. Редактор предлагает ясную формулировку действия, но не блокирует текст по грамматическим эвристикам.

Срок — последний допустимый календарный день в часовом поясе аккаунта, а не пожелание заняться сегодня. Задача без срока полноценна. Отмена отличается от выполнения. Проект можно сменить; ID задачи и её история сохраняются. Markdown-чек-листы внутри пояснения — пункты инструкции, не самостоятельные записи Task и не участники очереди действий.

### F05. Выбор из проекта в действия

У открытой задачи плана есть «Добавить в действия». Нажатие устанавливает `inActions=true`, добавляет ID в конец общей очереди и показывает в проекте отметку «В действиях». Повторное нажатие не создаёт записи и не меняет порядок. «Убрать из действий» сбрасывает флаг и убирает ID из очереди; задача остаётся в плане невыполненной.

Нажатие на название открывает одну и ту же карточку из проекта, действий или поиска. Редактирование сразу видно во всех локальных представлениях и после синхронизации на других устройствах. Самостоятельную задачу также можно выбрать в действия из её карточки.

### F06. Экран действий

Главный экран — плоская вручную упорядоченная очередь выбранных открытых задач из разных проектов. У строки: выполнение, формулировка, название проекта при наличии, реальный срок при наличии, открытие карточки и удаление из действий. Контекст ближайшего действия содержит проект, его ближайшее целевое состояние и пояснения задачи.

Порядок изменяется перетаскиванием и доступными кнопками/командами «Выше / Ниже». После выполнения строка исчезает из рабочей очереди; пользователь остаётся на экране, следующее действие становится первым. Никакого автоматического перехода в другой проект или инбокс. Просмотр выполненного доступен отдельно.

У каждой проектной задачи — переход именно в её проект. Общая кнопка «Открыть план проекта», ведущая в произвольный проект, отсутствует. Навигационный пункт «Проекты» ведёт в список проектов. Пустая очередь предлагает перейти к списку проектов или создать самостоятельную задачу. Жёсткие горизонты «сегодня/неделя», баллы приоритета и автосортировка по срокам не включены в согласованный минимальный экран.

### F07. Список проектов и карточка проекта

Список с поиском и фильтром «В работе / На паузе / Завершены / Отменены». Видны название и наличие выбранного следующего шага. В карточке:

1. Название проекта — редактируемое.
2. Видение конечного результата — редактируемый текст; может быть приблизительным.
3. Ближайшее целевое состояние — редактируемый промежуточный результат.
4. Следующий конкретный шаг — первая по общей очереди выбранная открытая задача этого проекта. Вычисляемая ссылка, а не копия заголовка.
5. План — все задачи проекта, включая невыбранные; выполненные/отменённые доступны отдельно. Порядок плана независим от очереди действий.
6. План и заметки в Markdown; связанные материалы и идеи.

Кнопки «Изменить» у результатов и «Изменить шаг» должны явно показывать возможность редактирования. Изменение шага редактирует связанную Task. Если выбранных задач нет, показать приглашение выбрать шаг из плана. Добавление задачи в план не выбирает её автоматически.

Статусы проекта — предложенное правило R1: пауза убирает его задачи из действий, но сохраняет их открытыми в плане; возобновление не восстанавливает старый выбор автоматически. Завершить/отменить проект с открытыми задачами можно только после решения: отменить оставшиеся или перенести/отвязать их. Никакого скрытого массового выполнения. Изменения выполняются атомарно.

### F08. Идеи

Название, Markdown-содержание и пояснение «Почему сохранил / чем пригодится»; редактирование, поиск, архив, удаление и явное «Пересмотрено». Идея может быть связана с проектом, но не становится его задачей. Сортировка для пересмотра — сначала давно не просмотренное; обычное открытие не обновляет дату пересмотра.

Превращение в задачу или проект создаёт объект с новым ID, сохраняет ссылку на исходную идею и выводит идею из очереди инкубации. Новая задача не выбирается в действия автоматически. Повтор доставки команды не повторяет преобразование. Можно отменить решение до подтверждения.

### F09. Справочная информация

Название и Markdown-текст; редактор и безопасный предпросмотр. Можно хранить самостоятельную запись, связать её с несколькими проектами или задачами, найти в общем справочнике и в контексте проекта. Связи не создают копий содержимого. Доступны редактирование, архив, поиск, корзина и экспорт Markdown.

Вложений, загрузки PDF и изображений в R1 нет. Обычные ссылки в Markdown допустимы. Внешние изображения не загружать автоматически: показывать ссылку. Raw HTML и исполняемые URL в предпросмотре не допускаются. Wiki-ссылки, трансклюзии и плагины Obsidian — за пределами R1.

### F10. Навигация и пересмотр

Разделы: «Действия», «Входящие», «Проекты», «Идеи», «Справочник». Поиск по названиям и текстам основных сущностей; результаты с типом и проектным контекстом, по умолчанию без корзины. Проекты без выбранного шага, старые идеи и необработанные входящие можно просмотреть и изменить без отдельной подсистемы обзоров. Специальные пуши и напоминания в R1 не входят; реальные сроки видны в списках.

### F11. Offline-first

После первого входа и загрузки данных доступны без сети: открытие приложения, создание/редактирование/удаление основных объектов, разбор входящих, выбор и порядок действий, выполнение, управление проектами, идеи, справочник, поиск и локальный экспорт. Изменения переживают обычную перезагрузку приложения при сохранности браузерного хранилища.

Сеть требуется для первого входа, операций пароля/сессий/API-токенов, получения изменений других устройств и серверных резервных копий. UI явно различает «локально», «ожидает отправки», «синхронизировано», «конфликт» и «ошибка». Автоматическая отправка при доступной сети и открытом приложении; фоновая доставка закрытой PWA не является гарантией R1.

### F12. Конфликты и восстановление изменений

Сохранить обе версии при несовместимых изменениях одного объекта с разных устройств. Показать поля/Markdown обеих версий, источник и варианты решения: оставить серверную, применить отредактированную объединённую, сохранить локальную версию отдельной записью. До решения исходные версии доступны. Конфликт удаления и редактирования не разрешается скрытым удалением или восстановлением.

Порядок очереди, составной разбор и закрытие проекта также проверяются на конфликт. Клиент не показывает успех серверной синхронизации только потому, что локальная запись прошла. Ошибка хранения не очищает редактор.

### F13. Экспорт, восстановление, корзина

Полный версионированный JSON-экспорт аккаунта; локальный экспорт включает несинхронизированные пользовательские данные и сообщает о pending/conflict. Импорт этого формата в R1 нужен для восстановления и не является импортом Obsidian. Для первой версии импорт разрешён в пустое пространство; смешивание двух заполненных аккаунтов — вне R1. Перед импортом показать состав, проверить целостность, применить атомарно.

Markdown-экспорт проектов (результаты, план, чек-листы и ссылки на IDs), идей и материалов — ZIP с отдельными `.md` и manifest.json для связей. Это читаемая выгрузка, не полный формат восстановления. Безопасные имена файлов; одинаковые названия различать суффиксом ID.

Удалённое хранится в корзине 30 дней с восстановлением. Переход в корзину проекта сохраняет задачи и связи, но убирает задачи из действий. Восстановление не активирует их автоматически. До окончательной очистки материал и его связи доступны для восстановления. Зависимости не удалять каскадом без документированной команды и решения пользователя.

### F14. API и внешние инструменты

Все функции клиента доступны через версионированный API с одинаковыми доменными правилами. В R1 предоставить scoped API-токены владельца, возможность отзыва и журнал действий интеграций. Минимальные области: чтение, добавление входящих, запись основных объектов; экспорт выдавать отдельным разрешением. Внешний клиент не получает пароль или браузерную сессию.

Встроенные инструменты пока описываются как будущие адаптеры к тому же слою команд. Не реализовывать выполнение произвольного кода, передачу содержимого сторонним провайдерам или автоматически действующего агента без отдельной спецификации. API R1 уже позволяет создать будущий MCP-адаптер, не меняя модель задач.

## 6. Нефункциональные требования

Численные цели ниже — предложенные критерии приёмки, не обещания существующего прототипа.

| ID | Требование и проверяемый критерий |
|---|---|
| N01 | Надёжность: локальная запись объекта и команды в очередь синхронизации атомарны; server ack только после транзакции БД. Повтор команды не создаёт дублей. |
| N02 | Офлайн: полный путь F11 проходит в режиме Offline после первой загрузки, включая закрытие и повторное открытие. Потеря браузерного хранилища не маскируется под пустой аккаунт. |
| N03 | Отзывчивость: при 10 000 задач и 2 000 текстовых записей до 20 КБ каждая, локальные выбор/сохранение p95 ≤300 мс, поиск p95 ≤500 мс. Измерять на зафиксированном телефоне среднего класса и desktop, указывать модель и браузер. |
| N04 | Синхронизация: при двух активных клиентах, RTT ≤100 мс и исправном сервере, 95% обычных изменений до 20 КБ видны на втором ≤10 с; конфликт показывается в том же цикле. |
| N05 | API: p95 обычной одиночной команды ≤500 мс без учёта сети при 5 активных сессиях на тестовом сервере 2 vCPU/4 ГБ RAM. Импорт, экспорт и парольный KDF измеряются отдельно. |
| N06 | Интерфейс: русский язык; ширины 360, 390, 768, 1440 px, масштаб 200%, клавиатура и экранный диктор для основных сценариев. Касания ≥44×44 px, цвет не единственный признак выбора. |
| N07 | Совместимость R1: актуальная стабильная и предыдущая основная версия Chrome/Edge/Firefox desktop и Safari macOS/iOS, Chrome Android на момент приёмки; конкретные версии записать в отчёт. Установка PWA предлагается только где поддерживается. |
| N08 | Безопасность: TLS, парольные хеши, проверка владельца каждого объекта, безопасный Markdown, CSRF для cookie-запросов, ограничение попыток входа, отзыв сессий/токенов. Секреты и пользовательские тексты не попадают в логи. |
| N09 | Резервирование: ежедневная копия серверной БД, хранение 30 дней, копия вне рабочего сервера. Цели RPO ≤24 ч, RTO ≤4 ч при доступной инфраструктуре; подтвердить тестовым восстановлением. |
| N10 | Обновление: версионированные миграции сервера и локальной БД; не терять outbox/черновики при обновлении PWA. Старая вкладка получает понятное уведомление о несовместимом API. |
| N11 | Наблюдаемость: readiness/liveness, ошибки и длительности команд, состояние заданий резервирования. Без сторонней аналитики содержимого по умолчанию. |
| N12 | Переносимость: размещение на сервере пользователя за Nginx; конфигурация в окружении, документация развёртывания, обновления и восстановления. Бизнес-правила не зависят от React или браузерного DOM. |

## 7. Приёмка R1

| Тест | Сценарий и ожидаемый результат | Требования |
|---|---|---|
| A01 | Создать задачу в проекте: она есть в плане и отсутствует в действиях. Выбрать дважды: в действиях одна запись с тем же ID. | F04–F07, N01 |
| A02 | Изменить заголовок и выполнить задачу из действий: изменения видны в проекте; следующий пункт плана сам не выбран. | F05–F07 |
| A03 | Убрать задачу из действий: она осталась открытой в плане. Вернуть выполненную: статус открытый, выбор требует явного решения. | F04–F06 |
| A04 | Действия из трёх проектов; открыть название проекта у каждой: открывается соответствующий проект, общей ссылки на один план нет. | F06–F07 |
| A05 | Изменить название/видение/целевое состояние; изменить следующий шаг: контекст и задача обновляются во всех представлениях. | F07 |
| A06 | Создать все основные сущности офлайн, разобрать входящее, изменить очередь, перезапустить и подключить сеть: всё сохранено, ID и связи совпадают на втором клиенте. | F02–F12, N01–N04 |
| A07 | Два клиента изменяют один объект; edit/delete; изменение проекта при закрытии: конфликт сохраняет обе версии, решение не затирает новое изменение. | F12 |
| A08 | Из одного входящего создать проект, две задачи и материал; ошибка одного объекта не оставляет частичного результата. Повтор operationId не создаёт дублей. | F03, N01 |
| A09 | Превратить идею в проект, повторить запрос: один результат, связь с идеей сохранена, новая работа не выбрана автоматически. | F08 |
| A10 | Один материал связан с двумя проектами: редактирование общее; удаление одной связи не удаляет материал. Script/опасная ссылка не исполняются. | F09, N08 |
| A11 | Полный JSON → пустой аккаунт: восстановлены ID/связи/состояния; битая ссылка отклонена до записи. Markdown ZIP читается без приложения. | F13 |
| A12 | Отозвать токен: новые запросы им запрещены. Токен inbox:create не может читать проекты, менять задачи или экспортировать аккаунт. | F14, N08 |
| A13 | Истекла сессия при pending-данных: локальная работа сохранена; после входа синхронизация продолжается. Выход не теряет pending без предупреждения и выбора. | F01, F11 |
| A14 | Ошибка/переполнение локального хранилища: ввод остаётся, подтверждения сохранения нет. Обновление PWA не удаляет очередь. | N01, N02, N10 |
| A15 | Два клиента одновременно переставляют действия или выбирают задачу: нет дублирующих ID, молчаливой потери порядка или несоответствия флага и очереди. | F05, F12 |
| A16 | Пауза проекта очищает его выбор; возобновление не возвращает его в очередь. Закрытие с открытыми задачами требует решения по ним. | F07 |
| A17 | Выполнить основные сценарии на desktop и мобильных viewport, клавиатурой и экранным диктором; замерить N03–N05. | N03–N07 |
| A18 | Восстановить резервную копию в отдельное окружение, проверить содержимое и связи; зафиксировать время. | N09 |
| A19 | Поиск работает офлайн, находит задачи без проекта и материалы; корзина исключена. Восстановленный проект не активирует задачи. | F10, F13 |
| A20 | Сменить пароль/отозвать сессию, запросить чужой ID тестовым аккаунтом: доступ закрыт; локальные несинхронизированные записи не уничтожаются. | F01, N08 |

Готовность R1: все функциональные требования реализованы, A01–A20 пройдены, измеримые N-требования подтверждены отчётом; изменения объёма согласованы владельцем. Прототип HTML и локальные проверки не доказывают готовность сервера, офлайн-синхронизации или мобильных клиентов.

Техническое устройство и контракт API: [architecture.md](architecture.md). Порядок реализации: [implementation.md](implementation.md).
